  • Apache, Tomcat, OpenJDK 기반
  • 사용자 규모 확대

45초. AWS 서비스 연결에는 인터페이스 VPC 엔드포인트 6개를 사용한다. 기존 추산에서 월 고정 요금은 56.94 USD로, NAT 게이트웨이 2개 구성의 93.44 USD보다 36.50 USD 낮다. 이 비교에는 데이터 처리·전송 요금이 빠져 있으며 엔드포인트는 일반 인터넷 통신을 대신하지 않는다. 운영 서버는 인터넷 출구 없이 AWS 서비스에 사설 연결한다. NAT 게이트웨이 1개 구성은 더 저렴하지만 한 AZ의 장애가 다른 AZ의 통신에도 영향을 줄 수 있어 비교 기준에서 제외했다. 웹은 micro에서 성능 요구를 충족해 t4g.micro 2대를 선택했다. WAS는 기본 메모리 사용량을 고려해 t4g.small 2대를 선택했다. 기존 추산에서 t3.micro와 t4g.micro의 시간당 비용은 각각 0.0130, 0.0104 USD이며, t3.small과 t4g.small은 각각 0.0260, 0.0208 USD다. 같은 크기의 t3 대비 시간당 비용이 20% 낮다. 전체 월 고정 요금 추산은 부록을 참고한다. 비용 항목별 과금 범위 참고: AWS VPC 요금. 사설 연결 참고: AWS PrivateLink를 통한 AWS 서비스 접근. 비교 막대 표현 참고: Datawrapper 비교 열, 직접 레이블.

웹 서버와 CloudFront

양진현

Apache 리버스 프록시

<VirtualHost *:80>
    ProxyAddHeaders On
    ProxyPreserveHost On
    RewriteEngine On
    # /petclinic 으로 오면 /petclinic/ 으로 301
    RewriteRule ^/petclinic$ https://%{HTTP_HOST}/petclinic/ [R=301,L]
    # ttl=55: ALB 유휴 제한(60초)보다 먼저 닫는다
    # addressttl=30: ALB IP가 바뀌어도 30초 안에 다시 조회
    ProxyPass        "/petclinic/" "http://<INTERNAL_ALB_DNS>/petclinic/" ttl=55 addressttl=30
    ProxyPassReverse "/petclinic/" "http://<INTERNAL_ALB_DNS>/petclinic/"
</VirtualHost>
  • /petclinic/만 WAS로 넘기고, 나머지는 Apache가 직접 응답
  • 내부 ALB는 IP가 아니라 DNS 이름으로 가리킨다.
  • SELinux에서 httpd_can_network_connect 허용

45초. ttl을 ALB 유휴 시간보다 짧게 두는 이유(ALB가 먼저 끊은 연결을 다시 쓰면 502)를 한 문장으로.

DNS = Domain Name System SELinux = Security-Enhanced Linux

CloudFront와 외부 ALB 보호

CloudFront (정액 요금제 Free)

  • 사용자 구간만 HTTPS. ALB에는 인증서가 없어 오리진은 HTTP
  • 동적 페이지라 캐싱 비활성화, 쿼리 문자열과 쿠키는 모두 전달
  • 오류 시 S3의 오류 페이지 (/pet_*, OAC)
  • WAF 속도 제한: IP마다 5분에 300건 (현재 모니터 모드)

외부 ALB에 CloudFront만 닿게

  1. 보안 그룹: CloudFront 관리형 접두사 목록만 허용
  2. 리스너: 비밀 헤더를 포함한 요청만 전달, 나머지는 403

45초. VPC 오리진을 쓰면 ALB를 internal로 둘 수 있지만 정액 요금제 Business(월 200 USD) 이상이 필요해서 internet-facing ALB + 두 겹 보호를 택했다고 말한다.

HTTPS = HTTP Secure HTTP = Hypertext Transfer Protocol OAC = Origin Access Control

인터넷이 없는 ARM 부하 발생 인스턴스에 패키지 버킷으로 k6 실행 파일을 반입했다. 테스트 데이터 10만 건을 적재한 뒤 조회·등록·수정 요청을 섞어 800 RPS로 5분간 시험했다. p95 응답 시간은 95 ms였고 실패율은 0%였다. 웹은 CPU와 메모리가 모두 70% 아래였다. WAS는 메모리 55.3%는 기준을 충족했지만 CPU가 75.8%로 기준을 넘었다. RDS CPU는 44.3%로 기준을 충족했고 가용 메모리는 601.3 MiB였다. WAS는 CPU 기준을 넘어 ASG 자동 확장으로 부하 증가에 대응한다.

p95 = 95번째 백분위수
